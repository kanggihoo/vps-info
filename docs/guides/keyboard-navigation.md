# 키보드 탐색과 상세 도구

2026-10-02 인터뷰에서 합의하고 구현한 동작을 정리한다.
Feed Navigation Order 저장은 [ADR-0016](../adr/0016-persist-feed-navigation-order.md), 화면 모양은 [DESIGN.md](../../apps/web/DESIGN.md)를 따른다.

## 고정 단축키

| 키 | 동작 |
|---|---|
| `1` | Feed 목록으로 포커스 이동 |
| `2` | Entry 목록으로 포커스 이동 |
| `3` | 현재 상세로 포커스 이동 |
| `B` | 현재 상세 Entry의 Bookmark 토글 |
| `R` | 현재 상세 Entry의 원문 읽기 토글 |
| `C` | 현재 상세에 보이는 내용의 Markdown 복사 |
| `T` | 현재 상세 Entry의 번역 실행 또는 원문·번역 표시 전환 |
| `O` | 현재 상세 Entry의 원문 링크를 새 탭으로 열기 |
| `D` | 현재 상세 Entry의 대화 열기·닫기 |

화면에 표시하는 영문 키는 대문자로 표기하지만 Shift를 누를 필요는 없다.
영문 키는 물리 키 위치인 `KeyboardEvent.code`를 기준으로 인식하여 한영 전환 상태와 무관하게 같은 키를 쓴다.

- 단축키는 앱의 읽기 패널 내부에 포커스가 있을 때만 동작한다.
- 입력창, Textarea, Select, 편집 가능한 영역과 한글 조합 중에는 읽기 단축키를 실행하지 않는다. 입력창의 Enter 전송과 Shift+Enter 줄바꿈을 유지한다.
- Ctrl, Cmd, Alt 조합은 가로채지 않는다. 브라우저 단축키와 일반 선택 복사를 유지한다.
- 버튼 작업은 키를 계속 누르는 동안 반복 실행하지 않는다. 목록 방향키 이동은 반복 입력을 허용한다.
- 처리 중이거나 지원하지 않는 작업은 해당 버튼과 같은 조건으로 실행하지 않는다.
- Feed Group 내부 탭·선택지, 대화 입력, 메뉴·Dialog, 드래그 정렬 중에는 각 컨트롤의 키 동작이 우선한다.
- 사용자가 직접 키를 바꾸는 설정은 제공하지 않는다.

## 패널 포커스와 목록 탐색

패널 이동은 포커스만 옮긴다. 다른 Feed나 Entry를 자동으로 열거나 Opened At을 기록하지 않는다.

- Feed 목록과 Entry 목록은 마지막으로 포커스했던 표시 항목으로 돌아간다. 해당 항목이 없으면 현재 선택된 항목, 그것도 없으면 첫 항목으로 이동한다.
- 목록의 이름 링크에 포커스가 있을 때 위·아래 방향키는 표시 순서의 이전·다음 항목으로 포커스를 옮긴다. 양 끝에서는 멈춘다.
- Feed 목록의 탐색은 Stream·Ranked 경계를 넘을 수 있다. 정렬은 각 구역 안에서만 가능하다.
- Enter는 포커스한 Feed 또는 Entry를 연다. Feed Group은 기존 변형 선택 규칙으로 Feed 하나를 연다.
- Entry를 열면 상세 컨테이너로 포커스를 옮긴다. 상세 내부 버튼·링크는 기존 Tab 순서로 접근한다.
- `3`은 상세 컨테이너로 이동한다. 현재 선택한 Entry가 없으면 새 Entry를 자동으로 열지 않는다.
- 목록 탐색 중에는 포커스한 항목이 보이도록 해당 목록 내부에서만 스크롤한다. 직접 목록을 스크롤한 결과로 Read Cursor가 이동하는 기존 규칙은 유지한다.
- 모든 포커스는 기존 포커스 링으로 표시한다. Stream 목록의 무한 스크롤과 Ranked 목록의 빠짐 구역은 현재 렌더링·로딩 규칙을 유지한다.

## 좁은 화면의 상세 유지

Feed 순서 변경 기준은 768px이고, 상세가 목록을 덮는 기준은 1024px이다. 두 기준을 구분한다.

| 화면 너비 | Feed 순서 변경 | 목록과 상세 |
|---|---|---|
| 768px 미만 | 제공하지 않음 | 가로 Feed 탭, 상세가 목록을 덮음 |
| 768px 이상 1024px 미만 | 세로 사이드바에서 가능 | 상세가 목록을 덮음 |
| 1024px 이상 | 세로 사이드바에서 가능 | 목록과 상세가 나란히 보임 |

1024px 미만에서 상세를 보고 `2`를 누르면 상세의 표시만 숨겨 목록을 보여 준다.
현재 상세 Entry와 원문 요청은 유지한다. 숨겨진 상세는 포커스·스크린 리더 탐색 대상에서 제외하되 컴포넌트는 유지한다.
`3`을 누르면 같은 상세를 다시 보여 주고 포커스를 옮긴다. 받아 둔 원문과 상세 스크롤 상태를 유지한다.
`1`로 Feed 목록에 포커스를 옮기는 것만으로도 현재 상세를 종료하지 않는다.

- 목록을 스크롤하거나 방향키로 탐색하는 동안 원문 가져오기는 계속된다.
- 다른 Entry 또는 다른 Feed를 열면 이전 상세와 원문 요청을 종료한다. 이전 Entry의 원문을 별도 캐시에 남기지 않는다.
- 기존의 상세 닫기 동작은 선택을 해제하고 원문 요청을 취소한다. 목록 이동 단축키는 닫기 동작과 구분한다.
- 숨겨진 상세의 작업 단축키는 실행하지 않는다. 먼저 `3`으로 상세를 표시한다.
- 좁은 화면에서 넓은 화면으로 바뀌면 유지 중인 상세를 다시 나란히 표시한다. 화면 크기 변경만으로 원문을 다시 요청하지 않는다.

상세를 열어 두는 동안 그 요청과 결과를 유지하는 것은 ADR-0011의 현재 상세 상태에 해당한다.
종료한 Entry의 본문을 캐시하거나 DB에 저장하는 기능은 추가하지 않는다.

## 정렬용 키보드

768px 이상에서 각 Feed·Feed Group 줄의 손잡이에 Tab으로 포커스할 수 있다.

1. Space 또는 Enter로 이동을 시작한다.
2. 위·아래 방향키로 같은 구역 안에서 한 줄씩 옮긴다.
3. Space 또는 Enter로 위치를 확정하고 자동 저장한다. Escape로 취소하면 저장하지 않는다.

이동 중에는 읽기 단축키와 목록 탐색보다 정렬 동작이 우선한다. 이동 결과가 같으면 저장하지 않는다.
저장 중에는 추가 정렬을 막는다. 실패하면 마지막 저장된 순서로 되돌리고 오류와 재시도 동작을 표시한다.
포커스는 옮긴 줄의 손잡이에 유지하고, 이동 결과와 저장 상태를 스크린 리더에도 알린다.

## 실행과 결과 표시

마우스 클릭과 단축키는 같은 작업 함수와 상태 표시를 사용한다.

| 상황 | 표시 |
|---|---|
| 실행 가능한 도구 단축키 인식 | 해당 버튼에 약 150ms 동안 기존 accent 배경 표시 |
| 복사 성공 | Clipboard 기록 성공 뒤 Lucide 체크 아이콘과 `복사됨` 표시, 약 1.5초 유지 |
| 원문 가져오기·번역 진행 | 기존 본문 로딩 표시와 버튼의 진행·비활성 상태 유지 |
| Bookmark·원문·번역·대화 전환 | 실제 상태를 버튼의 활성 배경·아이콘으로 표시 |
| 원문 새 탭 열기 | 링크 실행 시 버튼의 눌림 표시. 외부 페이지가 로딩 완료됐다는 성공 문구는 표시하지 않음 |
| 작업 실패 | 실패한 영역에 이유와 필요한 재시도 동작 표시 |
| 패널 포커스 이동 | 실제 이동 대상에 포커스 링 표시 |

툴팁에는 동작 이름과 키를 함께 표시한다. 예: `원문 읽기 R`, `복사 C`, `대화 D`.
아이콘은 `lucide-react`, Tooltip과 키 표시는 shadcn/ui 컴포넌트를 사용한다.
정렬은 `@dnd-kit/core`와 `@dnd-kit/sortable`로 구현하며, 일반 단축키와 포커스 이동은 브라우저 기본 기능을 쓴다.
복사 성공과 실패 등은 화면 표시와 함께 스크린 리더에도 알린다.
색·간격·움직임은 기존 DESIGN.md 토큰을 쓰고 prefers-reduced-motion을 따른다.

## 구현 경계

- 키 이벤트와 포커스 이동은 브라우저의 keydown과 focus()로 처리한다. 고정 키를 위해 DB·서버 API나 새 단축키 패키지는 추가하지 않는다.
- 도구 버튼 클릭과 단축키가 기존 동작 함수, 지원 여부, 실행 중 조건을 공유한다.
- 순서 저장만 ADR-0016의 조회·수정 API를 사용한다.
- 구현 시 확인할 핵심 흐름은 클릭과 드래그 구분, 구역 밖 이동 차단, 저장 실패 복구, 입력 중 단축키 제외, 목록 포커스와 Entry 열기 구분, 좁은 화면의 원문 요청 유지다.

# Spec: Entry를 앱 안에서 펼쳐 읽고, 제목·요약을 번역한다

- 상태: ready-for-agent
- 작성일: 2026-09-29
- 관련: ADR-0011(수용), ADR-0012(제안), ADR-0003, ADR-0007, ADR-0009, ADR-0010

## Problem Statement

목록에서 Entry를 누르면 원문이 곧바로 새 탭에서 열린다. 앱 안에서는 500자로 잘린 요약밖에 볼 수 없어서,
내용을 조금 확인하려 해도 매번 외부 사이트로 나갔다 돌아와야 하고 훑던 흐름이 끊긴다.

또 Feed 대부분이 영어라 요약을 읽는 데 품이 든다.

OpenAI News와 OpenRouter는 첫 수집 때 과거 글·모델 전체(2015년 글, 수백 개 모델)가 들어와
안 읽음으로 쌓여 있다. 필요 없는 옛 정보가 새 Entry를 가린다.

## Solution

화면을 `왼쪽 Feed 목록 | 가운데 Entry 목록 | 오른쪽 펼친 Entry` 3열로 바꾼다. 목록에서 Entry를 고르면 오른쪽에 제목, 메타 정보, 요약이 펼쳐진다.

- **읽기 버튼**을 누르면 앱이 원문 페이지를 가져와 본문만 뽑아 읽기 좋은 형태로 보여 준다. 가져온 본문은 저장하지 않는다.
- **번역 버튼**을 누르면 제목과 요약이 한국어로 번역된다. 한 번 번역한 것은 저장해 두고 다시 쓰며, 목록에도 번역 제목이 보인다.
- 원문으로 가는 링크는 오른쪽 도구줄의 버튼으로 옮긴다.

OpenAI News와 OpenRouter는 2026-01-01 이전에 게시된 항목을 더 이상 Entry로 받지 않고, 이미 받아 둔 옛 Entry는 정리한다.

## User Stories

### 펼쳐 보기

1. 사용자로서, 목록에서 Entry를 누르면 오른쪽에 그 Entry가 펼쳐졌으면 한다. 원문 사이트로 나가지 않고 내용을 확인하고 싶어서다.
2. 사용자로서, 펼친 화면에서 제목, Feed 이름, 작성자, 게시 시각, 요약을 보고 싶다. 원문을 열 가치가 있는지 판단하고 싶어서다.
3. 사용자로서, 펼친 화면에서도 카드 종류에 맞는 메타 정보(점수, 댓글 수, 스타, 가격 등)를 보고 싶다. 목록 카드에서 보던 정보를 잃지 않으려고.
4. 사용자로서, HN Entry를 펼쳤을 때 메타 줄의 댓글 수를 누르면 HN 토론 페이지로 가고 싶다. 지금 카드에서 하던 것처럼 하고 싶어서다.
5. 사용자로서, 펼친 Entry가 목록에서 선택된 것으로 표시되었으면 한다. 지금 무엇을 보고 있는지 알고 싶어서다.
6. 사용자로서, 목록에서 다른 Entry를 누르면 오른쪽이 그 Entry로 바뀌었으면 한다. 목록을 훑으며 차례로 보고 싶어서다.
7. 사용자로서, 아무 Entry도 고르지 않았을 때 오른쪽에 "Entry를 고르세요" 안내가 보였으면 한다. 빈 화면을 고장으로 오해하지 않으려고.
8. 사용자로서, 펼친 상태로 새로고침해도 같은 Entry가 펼쳐져 있었으면 한다. 읽던 자리를 잃지 않으려고.
9. 사용자로서, 펼친 Entry의 주소를 복사해 다시 열면 같은 Entry가 펼쳐졌으면 한다.
10. 사용자로서, 주소에 있는 Entry가 지금 Feed에 없거나 지워졌다면 안내가 나왔으면 한다. 빈 패널을 고장으로 오해하지 않으려고.
11. 사용자로서, Stream Feed 타임라인에서 Entry를 펼치고 싶다.
12. 사용자로서, Ranked Feed 순위표에서 Entry를 펼치고 싶다. 순위표에 오른 글도 앱 안에서 확인하고 싶어서다.
13. 사용자로서, Ranked Feed에서 펼쳤을 때 현재 순위와 순위 변동도 함께 보였으면 한다. 왜 이 글이 순위표에 있는지 맥락을 알고 싶어서다.
14. 사용자로서, Bookmark 목록에서 Entry를 펼치고 싶다. 모아 둔 글을 다시 읽는 곳이라서다.
15. 사용자로서, 펼친 화면에서 Bookmark를 켜고 끄고 싶다. 읽다가 바로 표시하고 싶어서다.
16. 사용자로서, 펼친 화면의 원문 열기 버튼으로 원문을 새 탭에서 열고 싶다.
17. 사용자로서, 도구줄의 아이콘 버튼에 마우스를 올리면 무슨 버튼인지 툴팁으로 알고 싶다.
18. 모바일 사용자로서, Entry를 누르면 펼친 화면이 전체 화면으로 떴으면 한다. 좁은 화면에서 3열은 읽을 수 없어서다.
19. 모바일 사용자로서, 뒤로 버튼이나 브라우저 뒤로 가기로 목록에 돌아가고 싶다. 목록 위치도 그대로이길 바란다.
20. 사용자로서, 다크 모드에서도 펼친 화면이 DESIGN.md 토큰대로 보였으면 한다.

### 읽음 상태

21. 사용자로서, Entry를 펼치면 그 Entry가 연 것으로 기록되었으면 한다(Opened At). 앱 안에서 읽은 것도 읽은 것이라서다.
22. 사용자로서, 이미 원문을 연 Entry를 펼쳐도 처음 연 시각이 바뀌지 않았으면 한다.
23. 사용자로서, Stream Feed에서 아래쪽 Entry를 펼치면 그보다 위(오래된 쪽) Entry도 훑은 것으로 쳐졌으면 한다(Read Cursor). 원문을 열었을 때와 같은 규칙이다.
24. 사용자로서, 펼친 Entry가 목록에서 읽은 모양(흐린 제목)으로 바뀌었으면 한다.
25. 사용자로서, 펼친 화면에서 원문 열기를 눌러도 Opened At과 Read Cursor가 지금처럼 동작했으면 한다.

### 원문 읽기 (Reader)

26. 사용자로서, 펼친 화면의 읽기 버튼을 누르면 원문 페이지의 본문이 오른쪽에 보였으면 한다. 원문 사이트에 가지 않고 끝까지 읽고 싶어서다.
27. 사용자로서, 본문을 가져오는 동안 로딩 모양(스켈레톤)이 보였으면 한다. 스피너는 쓰지 않는다.
28. 사용자로서, 본문의 제목, 목록, 링크, 이미지, 코드 블록, 표가 읽기 좋게 보였으면 한다.
29. 사용자로서, 저장소 Entry(Trendshift, HelloGitHub)의 읽기 결과로 README가 GitHub에서 보던 모습에 가깝게 보였으면 한다. 로고, 표, 접기(`<details>`)가 살아 있어야 한다.
30. 사용자로서, 본문의 링크는 새 탭에서 열렸으면 한다. 펼친 화면을 잃지 않으려고.
31. 사용자로서, 원문을 가져오지 못했다면(차단, 오류, 타임아웃, 빈 본문) "원문을 가져오지 못했습니다" 안내와 원문 링크를 보고 싶다.
32. 사용자로서, 추출된 본문이 짧거나 이상해도 그대로 보고 싶다. 판단은 내가 하겠다.
33. 사용자로서, 읽기 버튼을 다시 누르면 요약 화면으로 돌아가고 싶다.
34. 사용자로서, Product Hunt와 OpenRouter Entry에서는 읽기 버튼이 보이지 않았으면 한다. 본문 대신 제품·대시보드 화면이 나와 쓸모가 없어서다.
35. 사용자로서, 다른 Entry로 옮겨 가면 읽기 모드가 풀리고 새 Entry의 요약부터 보였으면 한다. 원하지 않는 외부 요청을 막고 싶어서다.
36. 사용자로서, 읽기 결과 안에 원문 사이트의 스크립트가 끼어 있어도 앱에서 실행되지 않았으면 한다. HN이 링크하는 사이트는 누구나 만든 곳이라서다.
37. 사용자로서, 본문을 가져오는 동안 다른 Entry로 옮기면 늦게 도착한 이전 본문이 새 Entry 위에 보이지 않았으면 한다.

### 번역

38. 사용자로서, 펼친 화면의 번역 버튼을 누르면 제목과 요약이 한국어로 바뀌었으면 한다. 영어를 빠르게 훑고 싶어서다.
39. 사용자로서, 번역하는 동안 버튼이 진행 중임을 보여 줬으면 한다.
40. 사용자로서, 번역된 Entry를 펼치면 한국어 제목이 크게, 그 아래 원제목이 작게 보였으면 한다. 기술 고유명사가 이상하게 번역됐을 때 원제목으로 확인하고 싶어서다.
41. 사용자로서, 번역된 Entry를 펼치면 요약이 처음부터 한국어로 보였으면 한다.
42. 사용자로서, 번역 버튼을 다시 누르면 요약을 원문과 번역 사이에서 오가고 싶다.
43. 사용자로서, 번역한 Entry는 목록에서도 한국어 제목만 보였으면 한다. 다음에 훑을 때 바로 읽히도록.
44. 사용자로서, 번역한 Entry는 새로고침한 뒤에도, Bookmark 목록과 순위표에서도 번역 제목으로 보였으면 한다.
45. 사용자로서, 이미 번역한 Entry의 번역 버튼을 눌러도 DeepL이 다시 불리지 않았으면 한다. 무료 한도(월 50만 자)를 아끼고 싶어서다.
46. 사용자로서, 요약이 없는 Entry도 제목만 번역되었으면 한다.
47. 사용자로서, 번역에 실패하면(한도 초과, 키 오류, DeepL 장애) 그 이유를 짧게 알려 주는 안내를 보고 싶다. 다시 누를지 판단하고 싶어서다.
48. 사용자로서, 번역 키가 설정되지 않은 환경(로컬 개발)에서는 번역 버튼을 눌렀을 때 번역을 쓸 수 없다고 알려 줬으면 한다. 다른 기능은 그대로 돼야 한다.
49. 사용자로서, 원문 본문(읽기 결과)은 번역되지 않는다는 것을 알고 싶다. 한도가 금방 바닥나지 않게 하려는 것이다.

### 게시일 하한

50. 사용자로서, OpenAI News에 2026-01-01 이전 글이 더 이상 새 Entry로 들어오지 않았으면 한다.
51. 사용자로서, OpenRouter에 2026-01-01 이전에 추가된 모델이 더 이상 새 Entry로 들어오지 않았으면 한다.
52. 사용자로서, 이미 받아 둔 옛 Entry가 목록과 안 읽음 수에서 사라졌으면 한다.
53. 사용자로서, 옛 Entry라도 Bookmark했거나 연 적이 있다면 남아 있었으면 한다. 내가 남긴 흔적은 지우지 않았으면 해서다.
54. 운영자로서, 게시일 하한 때문에 이번 수집에서 저장할 항목이 0건이어도 Feed가 실패로 기록되지 않았으면 한다. OpenRouter는 매번 모델 전체를 주므로 새 모델이 없는 날이 정상이다.
55. 운영자로서, Handler가 정말 0건을 돌려주면(정보원 구조 변경) 지금처럼 실패로 기록되었으면 한다. 조용히 망가진 Handler를 알아채야 해서다.
56. 운영자로서, 게시 시각이 없는 항목은 하한에 걸리지 않고 저장되었으면 한다.
57. 운영자로서, 게시일 하한을 선언하지 않은 Feed는 지금과 똑같이 동작했으면 한다. Product Hunt처럼 옛 게시일이 섞여 오는 Feed가 있다.

### 운영

58. 운영자로서, DeepL 키를 환경 변수 하나(`DEEPL_API_KEY`)로 넣고 싶다. 코드에 키를 두지 않으려고.
59. 운영자로서, 무료 키와 유료 키 중 어느 것을 넣어도 알맞은 DeepL 주소로 요청이 갔으면 한다.
60. 운영자로서, 원문 페이지 요청이 한 번에 너무 오래 걸리거나 너무 큰 응답을 받지 않았으면 한다(15초, 5MB). 서버가 묶이지 않게 하려고.
61. 운영자로서, API 응답에 Entry의 `raw`가 여전히 들어가지 않았으면 한다(ADR-0003).
62. 새 Feed를 추가하는 개발자로서, 게시일 하한과 읽기 버튼 숨김을 언제 설정하는지 가이드에서 알고 싶다.

## Implementation Decisions

### 도메인과 문서

- 용어는 CONTEXT.md를 따른다. 이번에 바뀐 정의는 다음과 같다.
  - **Entry**: 화면에서 원문 본문을 가져와 보여 줄 수 있지만, 그 본문은 저장하지 않으며 Entry의 일부가 아니다. 제목·요약 번역은 Entry에 딸려 저장한다.
  - **Opened At**: 앱에서 Entry를 펼치거나 원문 링크를 열면 찍힌다.
  - **Read Cursor**: 연 Entry(Opened At이 있는 Entry) 기준으로 움직인다.
  - **First Seen**: Feed가 게시일 하한을 선언했다면 그보다 먼저 게시된 항목은 Entry가 되지 않는다.
- "펼친 화면", "읽기 모드"는 화면 이름일 뿐 도메인 용어가 아니다. 코드 이름은 역할대로 짓되 CONTEXT.md 용어와 섞지 않는다.
- 원문 추출과 번역의 결정 근거는 ADR-0011에 있다. 목록 제목 자동 번역은 ADR-0012(제안)로 남기고 이번 범위에서 만들지 않는다.
- `docs/feeds.md`, `docs/guides/adding-a-feed.md`, `apps/web/DESIGN.md`(3열 배치, 펼친 화면, 도구줄), TypeScript convention(새 UI는 shadcn 레지스트리에서 먼저 찾는다)을 함께 고친다.

### 스키마

- 새 테이블 `entry_translation`을 둔다. Entry와 1:1이다.
  - `entry_id`: 기본키, `entry` 참조
  - `title`: 번역 제목, 필수
  - `summary`: 번역 요약. 원문 요약이 없으면 비어 있다
  - `translated_at`: 번역한 시각
- 목표 언어는 한국어 하나라 언어 컬럼을 두지 않는다. 실패 수·오류 컬럼은 ADR-0012를 만들 때 더한다.
- `entry.opened_at`의 컬럼 주석을 새 Opened At 정의에 맞춘다. 스키마 변경은 없다.
- 마이그레이션 하나가 옛 Entry를 지운다.
  - 대상: OpenAI News와 OpenRouter의 Entry 중 게시 시각이 2026-01-01(UTC) 이전이고, Bookmark도 Opened At도 없는 것
  - 두 Feed는 Stream Feed라 Rank Snapshot 참조가 없다
  - Read Cursor는 Entry id를 가리키는 값이라 지워진 id를 가리켜도 동작에 문제가 없다

### Feed 선언과 수집 코어

- Feed 선언에 선택 항목 `publishedSince`(날짜)를 더한다. `openai-news`와 `openrouter-models`에 `2026-01-01`을 선언한다.
- 수집 코어는 Handler 결과로 0건 검사를 먼저 한 뒤, 게시 시각이 하한보다 이른 항목을 버리고 저장한다.
  - 게시 시각이 없는 항목은 버리지 않는다.
  - 필터 뒤 0건은 성공이다.
  - Handler는 바뀌지 않는다. 저장 정책이라 코어의 일이다(ADR-0006).
- Ranked Feed에 하한을 선언하는 경우는 지금 없다. 만약 선언하면 필터는 Rank Snapshot 저장 전에 적용되어, 버린 항목은 순위에서도 빠진다.

### 서버 API

- **Entry 응답 모양**: 모든 Entry 응답(타임라인, 순위표 줄과 빠진 Entry, Bookmark 목록)에 `translatedTitle`과 `translatedSummary`를 더한다(없으면 `null`). `entry_translation`을 LEFT JOIN해서 채운다. `raw`는 여전히 내보내지 않는다.
- **Entry 하나 조회** `GET /api/entries/:entryId`: 주소로 바로 펼칠 때 쓴다. Entry와 Feed 제목을 돌려주고, 없으면 404다.
- **Opened At**: 기존 `POST /api/entries/:entryId/open`을 그대로 쓴다. 화면이 펼칠 때와 원문을 열 때 부른다.
- **원문 읽기** `GET /api/entries/:entryId/reader`:
  - Entry의 원문 주소를 가져와 추출한다.
  - 성공하면 `{ title, markdown, siteName?, byline? }`를 돌려준다. 값은 defuddle 결과에서 비어 있지 않은 것만 담는다.
  - 원문 요청이 2xx가 아니거나, HTML이 아니거나, 타임아웃·5MB 초과·연결 실패(내부망 주소 포함)이거나, 추출한 본문이 비었으면 502와 이유 코드(`upstream-status`, `not-html`, `timeout`, `too-large`, `unreachable`, `empty`)를 돌려준다.
  - Entry가 없으면 404다.
  - 결과는 저장하지 않는다.
- **번역** `POST /api/entries/:entryId/translation`:
  - 번역이 이미 있으면 DeepL을 부르지 않고 그 번역을 돌려준다.
  - 없으면 제목과 요약(있을 때만)을 DeepL 요청 한 번으로 번역해(`target_lang: KO`, 원문 언어는 자동 감지) 저장하고 돌려준다.
  - 응답은 `{ translatedTitle, translatedSummary }`다.
  - 오류는 이유 코드로 나눈다.

    | 상황 | 응답 | 이유 코드 |
    |---|---|---|
    | 키 없음 | 503 | `translation-disabled` |
    | 403(키 오류) | 502 | `translation-auth` |
    | 456(월 한도 초과) | 502 | `translation-quota` |
    | 429 | 502 | `translation-busy` |
    | 그 밖의 실패 | 502 | `translation-failed` |
    | Entry 없음 | 404 | — |

  - 실패는 저장하지 않는다.
- **주입점**: 서버 조립 함수가 선택 인자로 원문 페이지 가져오기 함수와 번역 함수를 받는다. 생략하면 실제 구현을 쓴다. 테스트는 가짜를 넣는다.

### 원문 페이지 가져오기와 추출 모듈

- 페이지 가져오기는 undici의 `request`를 쓴다. 수집기의 ofetch 클라이언트는 OpenAI 같은 Cloudflare 사이트에서 403을 받는다(2026-09-29 확인).
  - 브라우저와 비슷한 User-Agent, `Accept: text/html`, `Accept-Language`를 붙인다.
  - 리다이렉트는 최대 5번 따라간다.
  - 타임아웃은 15초이고, 본문은 5MB를 넘으면 끊는다.
  - 결과는 `{ status, html, finalUrl }`이다.
- 추출은 linkedom으로 DOM을 만들고 defuddle(정확한 버전 고정)을 `markdown: true`, `useAsync: false`로 부른다. `useAsync: false`는 X·YouTube 같은 제3자 API 호출을 막는다.
  - 상대 링크를 풀 수 있게 기준 URL로 최종 주소를 넘긴다.
  - 본문이 공백뿐이면 `empty`로 판정한다.

### DeepL 번역 모듈

- `DEEPL_API_KEY` 환경 변수를 읽는다. 키가 `:fx`로 끝나면 무료 주소(`api-free.deepl.com`), 아니면 유료 주소를 쓴다.
- 인증은 `Authorization: DeepL-Auth-Key` 헤더로 한다. 요청 하나에 텍스트 배열(최대 50개)을 보내고 같은 순서로 결과를 받는다.
- 인터페이스는 "텍스트 목록 → 번역 목록"이다. ADR-0012를 만들 때도 같은 함수를 쓴다.
- 오류는 HTTP 상태로 구분해 위 이유 코드로 바꿀 수 있는 형태로 던진다.
- 공식 `deepl-node` 대신 HTTP 호출 하나를 직접 쓴다. 쓰는 기능이 translate 하나뿐이다.

### 환경 변수와 배포

- `.env.example`에 `DEEPL_API_KEY=`를 빈 값으로, 설명 주석과 함께 더한다.
- compose의 `app` 서비스 환경에 `DEEPL_API_KEY`를 전달한다. 수집기에는 아직 필요 없다.
- 운영 비밀 값은 기존 비밀 관리 방식(sops)을 따른다. 실제 키 값은 저장소에 커밋하지 않는다.

### 화면

- **배치**: `lg`(1024px) 이상은 `Feed 목록 | Entry 목록 | 펼친 Entry` 3열이다. `lg` 미만은 Entry를 고르면 펼친 화면이 목록 칸을 덮고(모바일에서는 전체 화면), 뒤로 버튼과 브라우저 뒤로 가기로 돌아온다.
- **화면 주소**: `#/feeds/<feedId>/entries/<entryId>`와 `#/bookmarks/entries/<entryId>`를 더한다. 기존 주소는 그대로 동작한다. Entry를 고르면 해시가 바뀐다.
- **목록 카드**: 제목 링크가 원문을 열던 동작을 없애고, 카드를 누르면 펼친다. 키보드로도 고를 수 있어야 한다. 선택된 카드는 표시한다. 번역 제목이 있으면 그것만 보인다.
- **펼친 화면 도구줄**: shadcn `Button`(ghost 아이콘)과 `Tooltip`, lucide 아이콘을 쓴다.
  - Bookmark(`Star`)
  - 읽기(`BookOpenText`, 켜짐 상태 표시)
  - 번역(`Languages`, 켜짐 상태 표시)
  - 원문 열기(`ExternalLink`)
  - 모바일에서만 뒤로(`ArrowLeft`)
- **펼친 화면 본문**: shadcn `ScrollArea`, `Separator`, `Skeleton`, `Alert`를 쓴다. 필요한 컴포넌트는 공식 CLI로 추가하고, 받은 파일은 고치지 않는다.
- **Markdown 렌더링**: `react-markdown` + `rehype-raw` + `rehype-sanitize`(기본 허용 목록)를 쓰고, 글자 모양은 `@tailwindcss/typography`의 `prose`를 DESIGN.md 토큰에 맞춰 쓴다. 링크는 새 탭에서 연다.
- **읽기 버튼을 숨기는 Feed**: 화면 쪽 표에 둔다(`producthunt`, `openrouter-models`). 카드 종류 표와 같은 방식으로, Feed id를 먼저 보고 없으면 Feed Group id를 본다.
- **Ranked Feed에서 펼침**: 머리에 현재 순위와 변동을 보여 준다. 순위표에서 이미 받은 값을 넘겨 쓰고 따로 조회하지 않는다.
- **읽기 모드와 번역 표시 상태**: 펼친 Entry가 바뀌면 초기화한다. 번역이 이미 있는 Entry는 번역 표시가 켜진 채로 열린다.
- **Opened At**: Entry를 펼칠 때 기록하고, 화면의 Entry 상태도 즉시 바꾼다. Stream Feed에서는 지금 원문을 열 때처럼 Read Cursor 이동 요청을 보낸다.
- **데이터 흐름**: 번역 결과는 펼친 화면뿐 아니라 목록의 Entry 상태에도 반영한다. 지금 Opened At·Bookmark 변경을 목록에 반영하는 방식과 같다.

## Testing Decisions

- 좋은 테스트는 바깥에서 보이는 동작만 확인한다. HTTP 응답, DB에 남은 결과, 해시를 해석한 결과 같은 것이다. 내부 함수 호출 순서나 컴포넌트 구조에는 기대지 않는다.
- **서버 API 통합 테스트** (주 seam): 기존 API DB 테스트처럼 서버를 조립해 `inject`로 요청한다. 원문 가져오기와 번역 함수는 가짜를 주입한다.
  - 원문 읽기: 가짜가 기사 HTML을 주면 Markdown과 제목이 온다(실제 defuddle과 linkedom을 거친다). 200이 아닌 상태, 타임아웃, 빈 본문이면 502와 이유 코드가 온다. 없는 Entry는 404다.
  - 번역: 처음 부르면 가짜 번역 함수가 한 번 불리고 결과가 저장된다. 두 번째 부르면 가짜가 불리지 않는다. 요약이 없으면 제목만 보낸다. 키 없음, 한도 초과, 인증 오류는 각자의 응답과 이유 코드로 나오고 아무것도 저장되지 않는다.
  - Entry 응답: 번역이 있는 Entry는 타임라인, 순위표, Bookmark 목록, 하나 조회에서 `translatedTitle`·`translatedSummary`가 채워지고, 없으면 `null`이다. `raw`는 어디에도 없다.
  - Entry 하나 조회: 있으면 Entry와 Feed 제목이 오고, 없으면 404다.
  - 선례: 기존 API DB 테스트의 Feed·Entry 준비 방식과 `inject` 사용을 따른다.
- **수집 코어 DB 테스트**: 기존 Fetch Attempt DB 테스트처럼 가짜 `fetchEntries`를 주입한다.
  - 하한을 선언한 Feed는 하한 이전 항목을 저장하지 않고, 게시 시각이 없는 항목은 저장한다.
  - 전부 하한 이전이면 0건이지만 Fetch Attempt는 성공이다.
  - Handler가 0건이면 여전히 실패다.
  - 하한이 없는 Feed는 그대로 저장한다.
  - 테스트용 Feed 선언을 가짜로 넘길 수 있는 기존 방식을 따른다.
- **웹 단위 테스트**: 기존 화면 주소 테스트와 카드 종류 테스트처럼 순수 함수를 검사한다.
  - 새 해시(`entries/<id>`)를 해석하고 만든다. 잘못된 Entry id는 무시한다. 기존 해시는 그대로 해석한다.
  - 읽기 버튼 숨김 판정은 Feed id와 Group id 기준으로 한다.
  - 번역 API 호출과 오류 응답 해석도 기존 API 모듈 테스트처럼 확인한다.
- **DeepL 모듈 단위 테스트**: HTTP를 가짜로 바꿔 확인한다.
  - 키 끝(`:fx`)에 따라 주소가 갈린다.
  - 요청 본문이 텍스트 배열과 `KO`이고, 헤더가 인증 형식에 맞다.
  - 403·429·456·5xx가 각자의 오류로 바뀐다.
- 마이그레이션(옛 Entry 정리)은 자동 테스트를 두지 않는다. 적용 뒤 DB에서 두 Feed의 남은 건수와 Bookmark·연 Entry가 남았는지 확인한다.
- 화면 컴포넌트는 자동 테스트를 두지 않고, 앱을 띄워 3열, 모바일 전체 화면, 읽기, 번역, 새로고침 유지를 직접 확인한다.

## Out of Scope

- 목록 제목 자동 번역(수집 뒤 번역 루프, 대기·완료·실패 상태, 기존 Entry 번역). 설계는 ADR-0012(제안)에 있다.
- 원문 본문(읽기 결과) 번역.
- 읽기 결과 저장이나 캐시.
- 카드 종류별로 다른 펼친 화면. 저장소 스타·포크 요약, 모델 가격표, 논문 초록 정리 같은 것은 이후 고도화한다.
- AI 요약.
- HN 댓글 내용 가져오기. 메타 줄의 토론 링크만 유지한다.
- 목록에서 j/k 같은 키보드 단축키로 Entry를 넘기는 기능.
- GeekNews 원문 주소 수집. 지금처럼 GeekNews 글 페이지로 링크한다.
- DeepL 사용량(`/v2/usage`) 화면.

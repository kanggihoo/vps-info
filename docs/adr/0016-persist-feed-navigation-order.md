# ADR-0016: Feed Navigation Order를 개인용 공통 설정으로 DB에 저장한다

- 상태: 수용
- 결정일: 2026-10-02
- 관련: ADR-0010

## 배경

자주 보는 Feed와 Feed Group을 구역 안에서 위로 옮기고, 다른 기기에서도 같은 순서로 읽고 싶다.
현재 `apps/web/src/feed-group.ts:25`의 `buildSidebarSections`는 코드 선언 순서로 줄을 만든다.
`apps/web/src/feed-sidebar.tsx:43`의 목록은 768px 미만에서 가로 탭이 된다.
앱에는 사용자 개념이 없고 접근 제어는 상위 nginx의 Basic Auth가 담당한다(`README.md:27`).
Feed Group의 정의는 코드에 둔다는 ADR-0010은 유지하며, 사용자가 정한 배치만ㅋ DB에 저장한다.

## 결정

인터뷰와 최종 문서 검토에서 합의한 동작과 저장 설계를 기록한다.

1. **저장 범위**: 개인용 공통 순서 하나를 DB에 저장하고 모든 기기에서 공유한다.
2. **이동 단위**: Group 없는 Feed 한 줄 또는 Feed Group 한 줄이다. Group 안의 Feed는 별도로 이동하지 않는다.
3. **구역**: Stream 다음 Ranked라는 구역 순서는 유지하며, 이동은 각 구역 안에서만 허용한다.
4. **화면**: 768px 이상에서는 사이드바에서 직접 이동한다. 별도 편집 창을 열지 않는다. 768px 미만에서는 변경 기능을 제공하지 않고 저장된 순서로 가로 탭을 표시한다.
5. **자동 저장**: 이동을 완료했을 때 저장한다. 기본 순서 복원 기능은 제공하지 않는다. 저장 중에는 추가 이동을 막고, 실패하면 마지막 저장된 순서로 되돌린 뒤 오류를 표시한다.
6. **선택과 조회**: 접속·새로고침 시 저장된 순서를 읽는다. URL에 선택이 없으면 정렬된 첫 줄을 연다. 이동으로 현재 읽는 Feed를 변경하지 않는다. 첫 줄이 Group이면 기존의 변형 선택 규칙을 따른다.
7. **목록 변경**: 저장 순서에 없는 새 줄은 해당 구역 끝에 코드 선언 순서로 붙인다. 없어진 줄은 표시에서 제외한다. 기존 Group에 변형 Feed가 추가되어도 Group 위치는 유지한다.
8. **수정 범위**: Bookmark, LLM 선택, 테마 버튼과 Group 내부 탭·선택지의 배치는 기존 규칙을 따른다.
9. **클릭과 이동**: 각 줄에 포커스 가능한 드래그 손잡이를 둔다. Feed 이름은 선택 링크로 유지한다. 손잡이를 누르고 8px 이상 움직였을 때 드래그를 시작한다.
10. **키보드 이동**: 손잡이에 Tab으로 포커스한 뒤 Space/Enter로 이동을 시작하고, 위·아래 방향키로 같은 구역 안에서 한 줄씩 옮긴다. Space/Enter로 확정하면 저장하고, Escape로 취소하면 저장하지 않는다.

### 저장·API 설계

- 드래그 중 화면이 768px 미만으로 바뀌면 이동을 취소한다. 정렬 결과가 같으면 저장하지 않는다.
- `feed_navigation_order` 테이블 한 행에 `stream_order`, `ranked_order` JSONB 배열과 `updated_at`을 둔다. 배열 항목은 `{ kind: 'feed' | 'group', id: string }`이다. 단일 행 제약과 배열 형태 제약을 둔다. 사용자 테이블이나 Feed Group 정의 테이블은 만들지 않는다.
- `GET /api/feed-navigation-order`는 현재 선언과 저장 순서를 조합한 유효 순서를 반환한다. 저장값이 없으면 코드 선언 순서를 반환한다.
- `PUT /api/feed-navigation-order`는 두 구역의 전체 순서를 원자적으로 교체하고 저장 결과를 반환한다. 중복, 알 수 없는 항목, Group 내부 Feed의 독립 배치, 구역 간 이동은 거부한다. 현재 선언의 모든 표시 줄을 포함해야 한다. 목록이 배포로 달라졌다면 조회 후 다시 시도하도록 오류를 반환한다.
- 같은 배포의 우발적인 동시 저장은 마지막 DB 쓰기가 적용된다. 순서를 주기적으로 조회하는 기능은 추가하지 않는다.
- 조회 실패는 오류와 재시도 동작을 표시하고, 저장된 순서를 알 수 있을 때까지 이동과 기본 Feed의 자동 선택을 보류한다. 명시적 URL의 Feed는 읽을 수 있다.
- 테이블·컬럼 COMMENT를 포함한 Drizzle 마이그레이션을 추가한다. API 타입은 `packages/api-types`, HTTP 호출은 웹 API 모듈에 둔다.

## 검토한 대안들

### 브라우저에만 순서를 저장한다

- 장점: DB·API 변경이 없다.
- 단점: 다른 기기와 순서를 공유할 수 없다.
- 기각 사유: 한 번 설정한 순서를 모든 기기에서 쓰려는 요구를 충족하지 못한다.

### Feed마다 DB의 순서 컬럼을 추가한다

- 장점: Feed 조회에 순서를 함께 반환할 수 있다.
- 단점: 화면의 이동 단위인 Feed Group은 DB 행이 없다. 구성 Feed 여러 행을 함께 갱신해야 하고, 화면 배치가 수집 단위의 상태에 섞인다.
- 기각 사유: 코드에 있는 Group 정의와 사용자 배치를 분리하기 위해 화면 배치 전용 저장소에 둔다.

### 모바일에서도 순서를 변경한다

- 장점: 휴대폰만으로 설정할 수 있다.
- 단점: 가로 탭 스크롤과 이동 제스처를 구분하거나 별도 편집 화면을 제공해야 한다.
- 기각 사유: 순서 변경은 넓은 화면에서 하고 모바일에서는 같은 순서로 읽는 범위로 합의했다.

## 이유

수집 대상과 Group 구성은 코드가 소유하고, 개인이ㅂ 정한 배치는 DB가 소유한다.
개인용 설정 하나이므로 사용자별 설정이나 별도 동기화 절차 없이 여러 기기에서 순서를 유지할 수 있다.
좁은 화면의 변경 기능을 제외하면 기존 가로 스크롤을 유지하면서 PC에서 직접 이동하는 조작을 제공할 수 있다.

## 결과

- Feed Group 자체를 DB로 옮기지 않고도 Group의 배치를 저장할 수 있다.
- 모바일과 좁은 PC 창에서는 순서를 변경할 수 없다.
- 이미 열린 다른 화면은 새로고침할 때 저장 순서를 반영한다.
- Feed 또는 Group ID를 변경하면 새 항목으로 취급되어 구역 끝에 배치된다.
- 나중에 사용자별 순서를 제공하려면 저장 범위와 사용자 식별을 다시 설계해야 한다.

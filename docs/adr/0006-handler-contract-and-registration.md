# ADR-0006: Handler는 주입받은 HTTP 클라이언트로 Entry 목록만 돌려주고, 명시적 목록으로 등록한다

- 상태: 수용
- 결정일: 2026-09-24
- 관련: ADR-0002, ADR-0004, ADR-0005

## 배경

수집 방식은 RSS, 공식 API, HTML 스크래핑으로 제각각이다. 그래도 재시도, 타임아웃, 중복 판정, 저장,
실패 판정은 모든 Feed에 똑같이 적용돼야 한다(ADR-0002, ADR-0005). Handler는 정보원이 바뀔 때마다
고쳐지는 가장 자주 바뀌는 코드라서, 공통 정책이 Handler마다 따로 구현되면 곧 서로 어긋난다.

참고한 RSSHub(`diygod/rsshub`, commit `0a4ecdb0`)는 라우트 파일이 스스로를 선언하고, 디렉터리를 스캔해
자동 등록한다(`lib/utils/directory-import.ts`, 운영 환경에서는 빌드 단계에서 `assets/build/routes.js` 생성).
라우트 수가 3,000개가 넘기 때문에 필요한 방식이다. 이 프로젝트의 Handler는 5~10개 수준이다.

## 결정

1. **책임 범위**: Handler는 정보원에서 가져온 것을 Entry 목록으로 바꿔 돌려주는 데까지만 책임진다.
   재시도, 타임아웃, 중복 판정, 저장, 0건 판정은 코어가 한다.
2. **HTTP 클라이언트**: 코어가 설정을 마친 HTTP 클라이언트(`ofetch.create`)를 Handler에 주입한다.
   Handler는 그 클라이언트로 원하는 만큼 자유롭게 호출한다. 요청 여러 개, GraphQL, HTML 모두 된다.
3. **재시도 조건**: 공통 클라이언트는 타임아웃 10초, 재시도 2회다. 재시도하는 경우는 네트워크 오류,
   타임아웃, 408·425·429·5xx뿐이다. 나머지 4xx는 곧바로 실패로 처리한다.
4. **등록**: Handler는 `handlers/index.ts`에 import 한 줄로 등록한다. 디렉터리를 스캔하지 않는다.
5. **파라미터 타입**: Handler는 자기 파라미터의 타입을 선언한다. Feed 선언 파일에서 Handler에 넘기는
   파라미터를 컴파일할 때 검사한다.
6. **`allow_empty`의 위치**: Handler가 결과와 함께 돌려주지 않고 Feed 선언에 둔다. 0건이 정상인지는
   수집 방법이 아니라 Feed의 성격에 따라 정해지기 때문이다.

## 검토한 대안들

### 디렉터리 스캔으로 자동 등록 (RSSHub 방식)

- 장점: Handler 파일만 추가하면 등록된다.
- 단점: 빌드 결과의 경로와 확장자(`.ts` → `.js`)를 따로 처리해야 한다. Feed 선언의 파라미터를 타입으로
  검사할 수 없다.
- 기각 사유: Handler 수가 적어서 import 한 줄은 비용이 아니다. 타입 검사로 얻는 이득이 더 크다.

### Handler가 HTTP 요청과 재시도를 직접 다룸

- 장점: 사이트별 특수 처리(429 대기, 헤더)를 Handler 안에서 자유롭게 할 수 있다.
- 단점: 타임아웃과 재시도 정책이 Handler마다 달라진다. 실패 판정(ADR-0005)이 일관되지 않게 된다.
- 기각 사유: 공통 정책은 한 곳에 있어야 한다. 사이트별로 필요한 헤더는 주입받은 클라이언트에 요청 옵션으로 넘기면 된다.

## 이유

RSSHub가 공통 정책을 미들웨어에 모아 라우트 기여자가 건드리지 못하게 격리한 것과 같은 이유다.
정책은 코어에, 정보원 지식은 Handler에 둔다. 등록 방식만은 규모가 달라서 RSSHub와 반대로 간다.

## 결과

- Handler를 추가하려면 파일 하나와 `handlers/index.ts`의 한 줄이 필요하다.
- Handler는 코어 없이 가짜 HTTP 클라이언트만 주입해서 단독으로 테스트할 수 있다.
- Handler가 필요한 설정(토큰 등)을 선언하는 방식은 아직 두지 않는다. 토큰이 필요한 첫 Handler가 생길 때 추가한다.
- RSSHub 라우트는 엔드포인트와 파라미터를 알아내는 참고 자료로만 쓴다. RSSHub는 AGPL-3.0이므로 라우트 코드를
  복사하지 않는다. 공개 전환 가능성을 막지 않기 위해서다.
